# Experiment provenance and limitations

## 원 실험과 저장소 정리

학습과 설명 코드의 기준은 팀 과제의 `XAI_test.zip`에 들어 있던 `test22.py`와 `utils.py`입니다.
개별 초안의 문법 오류를 그대로 가져오는 대신, 학습과 설명이 연결된 이 버전을 선택했습니다.
게시 준비 과정에서는 파일명, 데이터 경로, 명령행 진입점, `device` 전달과 난수 설정을 정리했습니다.
학습 손실, Transformer 구조, 설명 계산은 원 코드에서 유지했습니다.
`provenance.json`은 원 파일의 SHA-256과 변경 범위를 기록합니다.

## 결과 해석

`results/historical_run.txt`는 기존에 보관된 실행 로그입니다. 이번 게시 과정에서 다시 학습한 결과가 아닙니다.
로그는 20 epoch를 기록하지만, 기준 소스의 기본 학습은 10 epoch입니다. CLI에서 `--epochs 20`을 지정할 수 있으나
원 로그와 정확히 일치하는 실행 구성·라이브러리·난수 상태는 확보되지 않았습니다.
두 클래스 중 `class=1`에 대한 F1을 모든 클래스의 평균 F1 또는 이상 클래스 F1으로 해석하면 안 됩니다.

## 점검할 분석상의 한계

1. 원 소스는 sktime의 `(sample, channel, time)` 배열을 축 변환 없이 `batch_first` Transformer에 넣습니다.
   따라서 모델의 sequence 축은 일반적인 시간 축과 다를 수 있습니다. 이 구성에서 얻은 결과를
   시간 축 attention 효과나 올바른 temporal attribution의 검증 결과로 주장하지 않습니다.
2. LIME은 마지막 sequence 위치만 사용합니다. 정규식으로 조건문 속 숫자를 모아 가장 큰 값을 피처 번호로
   사용하는 원 로직은 임계값을 피처 번호로 오인할 수 있습니다. 피처 순위의 정밀한 해석에는 수정·재실험이 필요합니다.
3. SHAP의 image_plot을 시계열 결과에 사용한 원 코드는 SHAP 버전과 반환 배열 형태에 따라 맞지 않을 수 있습니다.
   현재 버전에서 세 설명 기법의 전체 실행은 검증하지 않았습니다.
4. SHAP·Captum의 원 설치 버전과 전체 환경 잠금 파일은 확보되지 않았습니다. requirements의 두 의존성은 고정되지 않았습니다.
5. 새로 추가한 seed는 재실행 조건을 명시하기 위한 것으로, 원 실험의 난수 상태를 복원하거나 장치 간 동일성을 보장하지 않습니다.

저장소는 기존 팀 과제의 구현과 실험 기록을 보여 줍니다. 분석을 개선하려면 축 정의와 설명 코드를 먼저 정리하고,
검증셋을 분리해 재실험한 결과를 기존 기록과 구분해 추가해야 합니다.
